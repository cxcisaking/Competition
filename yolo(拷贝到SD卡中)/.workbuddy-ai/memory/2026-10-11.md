## 目录内容分析：D:\Competition\yolo(拷贝到SD卡中)

**结论**：这是一个基于 SDNN 推理框架的 YOLOv8 目标检测「aarch64 Linux 部署包」，用于边缘设备（竞赛/开发板）上跑绝缘子检测。

### 关键事实（已核实）
- `run_yolo`：AArch64 ELF 可执行文件（e_machine=0xB7）。符号含 SdnnModelBase / YoloInference / ClassificationModel，源路径 `/home/smartchip/sdnn_example/examples/{yolo/yolov8_main.cc,sdnn_sdk/model/sdnn_model_base.cc}`，依赖 OpenCV（cv::Mat/resize/putText/imwrite）与 TVM runtime（tvm::runtime::Module、DLTensor）。
- `deploy.json`：输入 images [1,640,640,3] uint8 NHWC RGB；输出 output npz float32 [1,6,8400]（= 4 box + 2 类）；accelerator=cpu；tracker="ap2:9090"。
- `mod.json`：TVM 计算图 JSON，180 个 null 节点 + 132 个 tvm_op（fused conv2d/sigmoid/multiply 等）。
- `mod.so` / `mod.params`：AArch64 ELF 共享库 + 10.5MB 权重。
- `sdnn_deploy.run`：Makeself 2.4.5 自解压包，label="sdnn aarch64 linux deploy package"，内含 `linux_install.sh` + `runtime_lib/libtvm_runtime.so.3.2.0` + `opencv_libs/libopencv_*4.5.5`，安装到 `/usr/lib` 后执行 ldconfig。
- `image_get.sh`：调用 `csi-test` 从 CSI 摄像头（video-evs0，640x480 YUYV）采集 N 帧到 test.yuv，再用 ffmpeg 转成 test%02d.png。
- `ffmpeg-7.0.2-arm64-static/`：johnvansickle 版 aarch64 静态 ffmpeg 7.0.2（含 GPLv3.txt、manpages）。
- `49.jpg` / `50.jpg`：连续两帧实拍图，内容为桌面上的电力绝缘子照片 → 推断检测目标为绝缘子（2 类）。

## 可用性核验（第二轮，"能直接用吗"）

- `run_yolo` 动态依赖（DT_NEEDED）：libtvm_runtime.so.3、libopencv_imgcodecs.so.405、libopencv_imgproc.so.405、libopencv_core.so.405、libstdc++.so.6、libm/libgcc_s/libc；解释器 `/lib/ld-linux-aarch64.so.1`。→ 必须在 AArch64 Linux 上运行。
- `sdnn_deploy.run` 提供的库（tar 清单）：runtime_lib/libtvm_runtime.so.3(.2.0) + opencv_libs/libopencv_{core,dnn,imgcodecs,imgproc}.so.405 → **与 run_yolo 所需 soname 完全匹配**，故需先跑它安装到 /usr/lib。
- `mod.so` 自身 DT_NEEDED 仅 libm/libc（作为 TVM module 由 libtvm_runtime dlopen 加载）。
- `run_yolo` 用法提示："APP Must Setup Model library path and image as input parameters" → 调用形式为 `./run_yolo <模型路径> <图片>`；它内部引用 **mod.json**，**不引用** deploy.json / mod.so / mod.params / main_graph / tracker / ap2:9090（后三者应属设备端平台框架，非 run_yolo）。
- 结论：**不能开箱即用**。需 (1) 在 AArch64 设备上先 `./sdnn_deploy.run` 装运行时；(2) 设备端需有 `csi-test` 与 CSI 摄像头（image_get.sh 依赖，包内没有）；(3) tracker `ap2:9090` 需对应服务存在。
- 环境无 `strings` 命令；解析 ELF/Makeself 用 Python（gzip 魔数 offset=18731）完成。

## 关键发现：不是通用 ARM64 程序（第三轮，"手机能不能跑"）

- `libtvm_runtime.so.3.2.0` 的 DT_NEEDED：libdl、**libsdrv-shm.so.1**、**libdrmdisplay.so**、**libhwconverter.so**、libpthread、libstdc++.so.6、libm、libgcc_s、libc、ld-linux-aarch64.so.1。
- 上述 3 个厂商私有库（sdrv 前缀，疑为 smartchip 平台驱动）**不在 sdnn_deploy.run 内**（该包仅含 opencv_libs/* + runtime_lib/libtvm_runtime*，共 16 个条目）→ 只能由**目标开发板的 BSP** 提供。
- libtvm_runtime 内含 `dlopen`、`npu`、`sdnn`、`ap2`、`tracker` 字符串。
- 因此该包**绑定特定 SoC + 板级 BSP**，不是"任意 aarch64 Linux 都能跑"。
- 手机（Android）不可行的硬性原因：① 链接 glibc `ld-linux-aarch64.so.1`，Android 是 Bionic `linker64`，ABI 不兼容；② Android 无 `libstdc++.so.6`（用 libc++）；③ 缺上述 3 个厂商驱动库；④ 需写 `/usr/lib`（要 root）；⑤ 采集依赖 `csi-test` + V4L2 CSI 摄像头（video-evs0），手机不适用。

## 项目性质（用户确认）

- **用途：比赛（竞赛）提交件**。因此部署目标 = 比赛方指定的 ARM64 开发板（同 SoC + 同 BSP），换硬件无意义。
- 板端自检命令：`uname -m`（应 aarch64）；`ls /usr/lib | grep -E "sdrv|drmdisplay|hwconverter|tvm_runtime|opencv"`；`ldd ./run_yolo`（不应有 not found）；再 `./run_yolo <模型目录> <图片>`。
- 在 PC/手机上只能验证"模型效果"（原始权重/ONNX），**无法验证本交付包的部署链路**。
